# 每日方向简报

当前项目内置 `daily_direction` 子模块，用于每天生成“美股 + A股 + 港股”混合方向简报，并可推送到 SeaTalk 群 webhook 或当前 tunnel 机器人对应的 SeaTalk bot。

## 数据源

- 三市场历史行情：Yahoo / `yfinance` 的近一年日线，复权；显式指定请求结束时间，检查每只股票的真实交易日期，滞后时再拉取一次。
- 美股独立核对：配置 `FUTUNN_APP_KEY` 和仓库外的 `FUTUNN_PRIVATE_KEY_FILE` 后，用富途只读正规时段快照校验 SPY/QQQ/DIA/SOXX 和 MU/AMGN/MSTR。历史 K 线继续使用 Yahoo，因为当前已验证的富途接入是快照；盘前、盘后和夜盘字段不混入日涨跌。下一美股正规交易时段开始后不拿当前快照验证前一日收盘。
- 交易日期：`exchange_calendars` 的 XNYS/XSHG/XHKG 日历确定最近已收盘的完整交易日，包括节假日和半日市；排除未收盘日 K。A股和港股晨报使用各自最近完整收盘日，不把晨间快照写进旧 K 线，也不反推或改写前一日收盘价。同花顺客户端保留供其他用途，当前晨报不使用其无明确日期的覆盖数据。
- 市场基准：美股 SPY（标普500ETF）、QQQ（纳指100ETF）、DIA（道指ETF）、SOXX（半导体ETF）；A股上证指数；港股恒生指数。消息明确标注 ETF/指数身份与数据日期。
- 样本广度：报告当前有效股票池的上涨、下跌、平盘数量和有效覆盖率。股票池线上拉取失败时回退到静态列表，样本数量会相应减少，不代表全市场广度。
- 资讯：`yfinance Ticker.news`，三市场轮流选取候选股，补充 SPY/QQQ/ASHR/FXI/2800.HK；只接受有日期、在过去 72 小时内的新闻。未取得资讯时写“无法据此认定没有事件”，不将抓取失败解释为没有宏观驱动。
- 分析：`reporting.py` 用市场基准与样本广度计算观察/进攻/防守，模型只从允许集合中选择关注和风险标的、新闻 ID。行情数字、日期、公司/行业身份、0–100 基准分由代码渲染，禁止模型新增或改写事实；未知行业不猜测。
- LLM：优先 GPT（存在 `OPENAI_API_KEY` 时），否则使用当前项目默认 Ollama。

## 手动运行

只打印，不推送：

```bash
.venv/bin/python scripts/daily_direction_push.py --test --no-llm
```

调用当前项目 LLM 配置生成总结：

```bash
.venv/bin/python scripts/daily_direction_push.py --test
```

实际推送到默认 SeaTalk bot 群：

```bash
.venv/bin/python scripts/daily_direction_push.py --send
```

通过已配置 tunnel 的 SeaTalk bot 主动推群：

```bash
export DAILY_DIRECTION_DELIVERY=seatalk-bot
export DAILY_DIRECTION_SEATALK_GROUP_ID="你的 group_id"

.venv/bin/python scripts/daily_direction_push.py --send
```

如果 `DAILY_DIRECTION_SEATALK_GROUP_ID` 为空，脚本会尝试使用 `SEATALK_ALLOWED_GROUP_IDS` 的第一个群 ID。

## LLM 选择

- 默认会加载 `.env` 和 `.env.local`。
- 若 `OPENAI_API_KEY` 存在，脚本默认优先把本次运行切到 `LLM_BACKEND=openai`。
- 若没有 GPT key，则沿用当前项目默认配置；本仓库当前默认是 `LLM_BACKEND=ollama` + `OLLAMA_MODEL=gemma4:31b-cloud`。
- 如果 LLM 调用失败或其 JSON 含未允许标的/字段，使用相同已校验数据生成规则版方向。
- 各市场最弱基准跌幅达到 3%，或基准跌幅达到 1% 且样本下跌比例达到 55%，或样本下跌比例达到 75%，该市场判为防守；全部基准上涨且下跌比例不超过 25% 才判为进攻，否则观察。跨市场任一防守时总判断防守。这是风险提示规则，尚未验证为可交易策略。

## Hermes 定时任务

Hermes 只负责调度，脚本自己生成内容并推送。工作日从 9:00 到 12:30 每半小时尝试一次；成功后当天相同 bot 群的后续运行会跳过。任一市场行情过期、有效覆盖不足 80%、市场基准缺失，或已配置的富途校验失败/与 Yahoo 不一致时，本次不生成或推送，等待下一次尝试。

```bash
DAILY_DIRECTION_DELIVERY=seatalk-bot
DAILY_DIRECTION_SEATALK_GROUP_ID="你的 group_id"
```

再创建 Hermes 定时任务：

```bash
hermes cron create "0,30 9-12 * * 1-5" \
  --name "stock-agent 每日方向简报" \
  --workdir /Users/kaiyi.wang/PycharmProjects/stock-agent \
  --script /Users/kaiyi.wang/PycharmProjects/stock-agent/scripts/daily_direction_hermes_job.sh \
  --no-agent
```

手动触发一次 Hermes job 可用：

```bash
hermes cron list
hermes cron run "stock-agent 每日方向简报"
```

如需在已成功发送的当天手动补发，可运行 `./scripts/daily_direction_hermes_job.sh --force-send`。

更正已发送内容时可加 `--force-send --correction`。正常运行会在 `~/.local/state/stock-agent/daily-direction-runs/<上海时间>/` 留存 `snapshots.json`、`news.json`、`prompt.txt`、`report.txt`；校验失败时保存 `quality-errors.json`，便于追查每个数字的来源。

如果希望 Hermes 再二次整理脚本输出，可以去掉 `--no-agent`，并在 prompt 里要求“保留标的和风险，只压缩成群消息”。第一版建议使用 `--no-agent`，稳定性更好。

## 常用参数

| 参数 | 说明 |
| --- | --- |
| `--markets us,cn,hk` | 选择市场，默认三市场都扫 |
| `--max-items 15` | 每个市场进入 LLM 总结的 baseline Top N，默认 15 |
| `--test` | 每个市场只扫少量标的，用于验证 |
| `--no-llm` | 不调用 LLM，直接使用规则版 |
| `--send` | 实际推送 SeaTalk |
| `--force-send` | 跳过当天发送记录，手动补发 |
| `--correction` | 给此次简报加更正说明 |
| `--output-dir` | 指定本次数据、提示词、报告的审计目录 |
| `--delivery webhook/seatalk-bot` | 选择群 webhook 或 SeaTalk bot OpenAPI |
| `--webhook-url` | 覆盖 `DAILY_DIRECTION_WEBHOOK_URL` |
| `--signing-secret` | 覆盖 `DAILY_DIRECTION_SIGNING_SECRET` |
| `--sign-mode auto/query/none` | 默认 `auto`，先尝试带签名，失败后降级无签名 |
| `--group-id` | 覆盖 `DAILY_DIRECTION_SEATALK_GROUP_ID`，仅 `seatalk-bot` 使用 |
| `--thread-id` | 可选，指定 SeaTalk thread |
